# Conversation grouping and metrics

Status: implemented, tested and release-built locally; deployment/review pending.

## Request

Collapse the mixed `exec`, `send_message`, and `followup_task` rows shown in Ryan's
screenshot, keep the useful collapsed-row metrics, add metrics to every entry,
and put totals at the top of Conversation.

## Implementation

- Fold consecutive tool entries, including mixed results, coordination, lifecycle
  calls and failures, into one row per uninterrupted run (up to the server's
  240-entry transcript bound, without the old 24-call split). Prose and approval
  requests remain separate. Show failure counts and warning styling on the group.
- Preserve every original call and result, native text-only rendering, expansion
  state, member-based reading anchors and pane isolation. Group keys no longer
  change when a result changes from pending/success to failure.
- Show recorded input/output tokens on individual messages, tool entries and all
  group summaries. Explicit zero stays zero; missing/invalid/overflowing usage is
  unavailable, never invented. One request's usage belongs to one entry, so other
  entries from that request may have no separately recorded usage.
- Show loaded message/tool/error counts and input/output/combined token totals
  above the scrollable conversation. Totals include entries hidden by Show
  filters, do not change with expansion, clear on pane changes/unavailability,
  and disappear outside Conversation.
- Label truncated views `Loaded totals (partial)`. These are recorded tokens in
  the bounded transcript, **not lifetime session spend or current context size**.
  Existing 4 MiB log-tail / 240-entry / 768 KiB response limits remain intact.
- Read Codex `token_count` request usage, without double-counting cached input,
  reasoning output, or repeated cumulative usage events. Do not attribute a
  preceding, missing request to a new entry or cross user/compact boundaries.
- Deduplicate Claude streaming usage by bounded native request ID, retaining
  final counters and assigning them once to a visible entry. Validate counters
  and overflow. No billing database, stored grains, session discovery, or
  auto-compaction policy changes.
